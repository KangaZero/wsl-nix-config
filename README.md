# WSL Arch + Nix Home-Manager Flake

KangaZero's dotfile/env flake. Runs on Arch (WSL2). Manage user pkgs via [home-manager](https://github.com/nix-community/home-manager).


## Defaults
- Shell: `zsh`
- Editor: `neovim` # My actual neovim config is not included.
- Tooling for languages: `typescript`, `python`, `rust` #technically most popular languages are possible due to `mise`
- Terminal: `alacritty` #config not included as it in exists in the Windows file directory

## Install Nix on Arch (WSL)

### 1. Prereq

WSL2 Arch running. Verify systemd on (needed for daemon install):

```bash
cat /etc/wsl.conf
# want:
# [boot]
# systemd=true
```

If missing, add → `wsl --shutdown` from Windows → relaunch.

### 2. Install Nix — pick one

#### Option A: pacman (Arch native pkg)

Fastest on Arch. Pulls from official `extra` repo:

```bash
sudo pacman -Syu nix
```

Add yourself to `nix-users` (skip if root):

```bash
sudo gpasswd -a "$USER" nix-users
```

Enable + start daemon (systemd required):

```bash
sudo systemctl enable --now nix-daemon.socket
```

Source Nix env in shell:

```bash
. /etc/profile.d/nix.sh
# or for fish/zsh: source equivalent file
```

Tradeoff: pkg version lags Determinate. Daemon config = stock. Good if you trust pacman lifecycle.

#### Option B: Determinate Systems installer (recommended)

Handle WSL quirks better than upstream script. Flakes pre-enabled:

```bash
curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install linux --no-confirm
```

#### Option C: Upstream multi-user installer

```bash
sh <(curl -L https://nixos.org/nix/install) --daemon
```

### 3. Enable flakes + nix-command

```bash
mkdir -p ~/.config/nix
echo 'experimental-features = nix-command flakes' >> ~/.config/nix/nix.conf
```

(Determinate installer enables these by default. Skip if used.)

### 4. Reload shell

```bash
exec $SHELL -l
nix --version   # verify
```

## Run This Flake

### Clone to expected path

home-manager looks for config at `~/.config/home-manager`:

```bash
git clone https://github.com/KangaZero/<this-repo>.git ~/.config/home-manager
cd ~/.config/home-manager
```

### First-time apply

No `home-manager` CLI yet → run via flake directly:

```bash
nix run home-manager/release-26.05 -- switch --flake .#root
```

`.#root` = `homeConfigurations.root` from `flake.nix`. Change if username differs.

After first switch, `home-manager` is on PATH:

```bash
home-manager switch --flake .#root
```

Shell alias from `home.nix`:

```bash
nixRebuild    # = (z ~/.config/home-manager && home-manager switch)
editNix       # = (z ~/.config/home-manager && nvim flake.nix)
```

### Dev shell (pre-commit hooks loaded)

```bash
nix develop
# entering shell → pre-commit hooks auto-install
```

Hooks fire on `git commit`: `deadnix` → `nixfmt-rfc-style` → `statix`.

### Update inputs

```bash
nix flake update           # bump all inputs
nix flake lock --update-input nixpkgs   # bump single input
home-manager switch --flake .#root
```

### Garbage collect old generations

```bash
home-manager generations           # list
home-manager expire-generations '-7 days'
nix-collect-garbage -d
```

### Rollback

```bash
home-manager generations           # find prev gen path
/nix/store/<hash>-home-manager-generation/activate
```

## Make zsh the Default Shell

home-manager enables zsh, but it does **not** touch `/etc/passwd` (system-owned on Arch). On first launch WSL still drops you in `bash`. Fix with a hybrid approach: imperative `chsh` for `$SHELL` correctness + declarative bash trampoline as a safety net.

### 1. Imperative: `chsh` (one-time, sets `$SHELL`)

Nix-installed shells aren't in `/etc/shells` by default, so `chsh` refuses. Add the path first:

```bash
echo "$(command -v zsh)" | sudo tee -a /etc/shells
chsh -s "$(command -v zsh)"
```

Verify:

```bash
getent passwd "$USER" | cut -d: -f7   # → ~/.nix-profile/bin/zsh
```

If you're not on a minimal install and `which` is missing, use `command -v` (bash builtin — always available).

### 2. Declarative: bash trampoline (already wired in `home.nix`)

`programs.bash.initExtra` execs zsh whenever an interactive bash session starts:

```nix
programs.bash = {
  enable = true;
  initExtra = ''
    if [[ $- == *i* ]] && [[ -z "$ZSH_VERSION" ]] && command -v zsh >/dev/null; then
      exec zsh -l
    fi
  '';
};
```

Re-apply after edits:

```bash
home-manager switch --flake .#root
```

Why both?

| Layer | Pros | Cons |
|---|---|---|
| `chsh` | Sets `$SHELL` env correctly (tmux, sudo, `make` rely on it) | Imperative, one-shot. Survives across rebuilds but not WSL distro reinstalls. |
| Bash trampoline | Declarative, version-controlled, reproducible | `$SHELL` stays `/bin/bash`; tiny exec overhead |

### 3. Restart WSL

From PowerShell:

```powershell
wsl --shutdown
```

Reopen → land in zsh.

### Caveat: nix-profile path churn

`~/.nix-profile/bin/zsh` is a symlink into the Nix store. GC + version bumps can change the underlying store path, but the symlink itself stays stable — `/etc/shells` keeps working. If you ever **remove** zsh from `home.nix`, the symlink breaks → login fails. Revert with `chsh -s /bin/bash` *before* removing.

Optional belt-and-suspenders: symlink into `/usr/local/bin` instead, so `/etc/shells` references a path Nix never touches:

```bash
sudo ln -s "$(command -v zsh)" /usr/local/bin/zsh
echo /usr/local/bin/zsh | sudo tee -a /etc/shells
chsh -s /usr/local/bin/zsh
```

## Lint Manually

Pre-commit runs all hooks. Run solo:

```bash
nix run nixpkgs#statix -- check .       # lint
nix run nixpkgs#statix -- fix .         # auto-fix
nix run nixpkgs#deadnix -- .            # dead code
nix run nixpkgs#nixfmt-rfc-style -- *.nix   # format
```

Note: `nix fmt` not wired (no `formatter` output in flake). Use commands above.

## Customize

Edit `home.nix`:
- Pkgs → `home.packages`
- Zsh → `programs.zsh` (catppuccin mocha theme, oh-my-zsh, fzf/z/git plugins)
- Neovim → `programs.neovim` (sideloads `~/.config/nvim/init.lua`)
- Aliases → `programs.zsh.shellAliases`

Edit `flake.nix`:
- Change `username` if not `root`
- Add inputs (e.g. dotfiles repo — commented stub present)
- Adjust home-manager branch (`release-26.05` → newer when avail)

Apply: `home-manager switch --flake .#<username>`.

## Troubleshoot

| Symptom | Fix |
|---|---|
| `flake does not provide attribute 'formatter.x86_64-linux'` | Expected. `nix fmt` not wired. Use `nix run nixpkgs#nixfmt-rfc-style`. |
| `error: experimental Nix feature 'flakes' is disabled` | Step 3 above. |
| `statix` hook fail on commit | Run `nix run nixpkgs#statix -- fix .` then re-stage. |
| systemd not running in WSL | Edit `/etc/wsl.conf`, `wsl --shutdown` from PowerShell. |
| `nixRebuild` alias missing | Apply flake once first — alias defined in `home.nix`. |
| `chsh: ... is not listed in /etc/shells` | `echo "$(command -v zsh)" \| sudo tee -a /etc/shells` first. See [zsh default shell section](#make-zsh-the-default-shell). |
| WSL still drops into bash on launch | `chsh` not run, or `wsl --shutdown` skipped. Bash trampoline in `home.nix` will catch you regardless after `home-manager switch`. |
| `which: command not found` | Use `command -v <cmd>` (bash builtin). Install via `pacman -S which` or add to `home.packages`. |
